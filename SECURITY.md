# Report security concerns privately

Email [jstn0513@gmail.com](mailto:jstn0513@gmail.com) with suspected security problems. Jstn-1g receives these reports and is the accountable human maintainer. Do not open a public issue for a vulnerability or sensitive-data exposure. Responses are best effort, with no guaranteed response time or emergency service.

The maintained version is the current `main` branch of community edition v0.1.0. This edition contains an adult-facing proposal, a static website, and its build and publication tooling. It is not a child-facing learning service. Report problems in the source, generated website, or repository workflows; older checkouts should be updated to the latest reviewed commit.

Include the affected commit or page, a clear description, minimal reproduction steps, and the likely impact. Remove credentials and personal data from examples. Do not upload child records, exploit a live service, or test systems you do not have permission to test.

Accidental sensitive-data exposure also needs private handling. Do not reproduce the exposed material in a public issue or pull request. Project responders must arrange removal and coordinate with the relevant hosting provider as needed; deleting a public file cannot guarantee that copies disappear.

The maintainer coordinates fixes and disclosure with the reporter where possible. Fixes are reviewed and tested before publication on `main`; public notices should explain the impact and remedy without exposing private report contents or personal data.

Automated code checks support review; they are not a security certification. No AI inbox access or continuous report monitoring is configured. Keep private reports out of AI tools; AI assistance may use only a sanitized technical description approved for sharing by the responsible human.
