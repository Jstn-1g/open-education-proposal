# Report security concerns privately

This is a local informational-site and documentation candidate. There is no hosted service, supported public release, or verified project security-reporting route yet.

Before publication, the repository owner must provide and test a private reporting route, identify who receives reports, and state realistic response expectations. A public issue is not a substitute. The launch information must name the supported version and explain how fixes and disclosures are coordinated.

For a later report, include the affected version or page, a clear description, minimal reproduction steps, and the likely impact. Remove credentials and personal data from examples. Do not upload child records, exploit a live service, or test systems you do not have permission to test.

Accidental sensitive-data exposure also needs private handling. Do not reproduce the exposed material in a public issue or pull request. Project responders must arrange removal and coordinate with the relevant hosting provider as needed; deleting a public file cannot guarantee that copies disappear.

No reporting address, response-time guarantee, or security certification is implied by this draft.
